# ADR 0001：手动记录、本地优先与 iOS 风格 PWA

日期：2026-10-08。状态：已采纳并实现为 0.1.0 本地开发预览，正式验收尚未完成。

## 背景

用户需要家用划船机教学、针对性训练和有氧 / 无氧方向计划，优先 iOS 原生风格与系统深色模式。用户先要求文档，随后授权开发；首版手动记录，后续再接设备。

空项目没有必须沿用的技术栈；工作区存在原生 PWA 与 React / TypeScript / Vite 项目，可参考组件与工程模式，但不直接共享业务状态或数据库。

## 决策

- 已确认范围：首版手动记录；已实施教学、计划、跟练、记录和 PWA 主链路。
- 建议架构：React / TypeScript / Vite + 原生 CSS / SVG；UI 与计时、计划规则、Repository 分层。初始化核对版本、许可、成本并保留锁文件。
- 建议数据：IndexedDB 保存结构化记录和会话；LocalStorage 只保存简单外观偏好；必须具备事务、版本、备份、导入预览与失败恢复。
- 建议交互：系统字体、原生输入、分组列表、四标签导航、Sheet；主题跟随系统且可手动覆盖。
- 建议计时：前台单调时钟，后台转挂起；恢复最近检查点，不将后台时间自动判为已完成训练。
- 建议部署：可独立托管的静态 HTTPS PWA，原生 SW 明确控制缓存与更新。托管供应商暂不决定。

## 备选与取舍

纯原生 JavaScript 的体积和依赖成本更低，但本项目有多个页面和可恢复训练状态；React / TypeScript 建议用于组件与数据契约可维护性，实际体积仍需测量。

完整移动 UI 框架可减少部分组件工作，但会增加运行时与主题定制成本；首版选择少量自有组件。原生 iOS 应用可直接使用 UIKit 和设备 API，但不满足当前 PWA 首版范围；后续硬件需求再单独评估。

首版无云同步有利于离线和最少数据收集，但本机数据必须备份，不能宣称多端自动同步。Safari 设备与后台限制见 [开发文档第 11 节](../../product/开发文档_V1.0.md#11-pwa离线与-ios-能力边界)，相关公开来源在主文档内。

## 验证与变更

实施补充：固定 Vite 8.0.16 安全修复版；预览使用 Node 原生服务器及真实安全头。当前内容为用户确认的 1.0.0；旧 draft-1 快照兼容，当前只提供非破坏性的备份合并。实际契约在 src/domain/types.ts。浏览器结果和真机限制见状态文件。

按主文档的 D1–D4 验证 UI、计时、事务、恢复、离线、更新和 iOS 真机。若体积、维护或设备能力证明建议不合适，先给出证据与替代方案，再记录新 ADR；不把尚未实现的建议写成运行事实。
