## 1. 项目背景与决策

家用划船机用户需要解决三个问题：怎样划得规范、今天应该练什么、怎样持续训练并看到自己的记录。产品围绕这三个问题建立教学、训练计划、跟练与记录闭环，以清晰可靠的流程替代复杂的指标堆叠。

### 1.1 已确认需求

- 支持动作规范教学、针对性训练、有氧与无氧方向的训练计划。
- UI 尽量接近 iOS 原生体验，支持 iOS 深色模式。
- 首版手动记录，后续再连接设备。此范围已由用户于 2026-10-08 确认。
- 已按文档开始开发；用户随后确认训练内容、指定 iPhone Air 模拟验收，并要求官方规则 SVG 动画与简化界面。

### 1.2 本文采用的设计假设

| 项目 | 首版设计假设 | 后续如何调整 |
| --- | --- | --- |
| 用户 | 成年普通家庭用户，包含新手及有一定运动基础者 | 未成年人、孕产期、术后与疾病康复需求单独设计 |
| 设备 | 使用脚蹬、滑座与拉柄的常见家用划船机；阻力与读数因机型不同 | 确认品牌型号后补充设备说明与数据 Adapter |
| 语言 | 简体中文，单位为分钟、秒、米、次/分 | P1 再评估多语言与其他单位 |
| 账号 | 首版无登录，无云同步 | 跨设备需要时再设计身份、同步与冲突策略 |
| 训练依据 | 主观用力程度、动作自评与实际完成情况 | 有可信设备数据后再加入配速、功率与心率辅助 |
| 技术 | React + TypeScript + Vite、原生 CSS、IndexedDB、原生 Service Worker | 已按方案实施；实际版本、许可与体积见依赖说明 |
| 教学素材 | 首版自有 SVG 分解示意和文字；真人视频属于 P1 | 不把尚未取得授权的外部视频列为离线资产 |

这些假设不影响文档交付；进入相关开发阶段时根据实际信息修订，不将其写成已确认事实。

### 1.3 目标与非目标

目标：让用户掌握基本动作、获得适合当前能力和时间的训练安排、完成有引导的训练、离线保存并备份记录。

首版不包含：医疗诊断或康复处方、自动动作评分、摄像头采集、AI 私人教练、社交排行榜、订阅支付、Apple Health 写入、后台持续训练播报与蓝牙自动采集。

PWA 使用 HTML、CSS 和浏览器控件实现 iOS 风格，不能直接调用 UIKit / SwiftUI 组件。字体优先系统字体，表单尽量使用原生输入与选择器，自绘底部标签栏、分组列表和 Sheet，保持平台熟悉的布局和交互。Apple 的标签栏用于切换顶层页面，不承担“开始训练”等动作。[Apple 标签栏指南](https://developer.apple.com/design/human-interface-guidelines/tab-bars)

## 2. 用户与关键场景

| 用户场景 | 主要需求 | 产品响应 |
| --- | --- | --- |
| 首次使用划船机 | 担心动作做错，不知道阻力怎样设置 | 设置说明、四阶段教学、低强度技术练习 |
| 久坐后恢复运动 | 时间有限，希望逐步建立习惯 | 低负担起步计划、可缩短课程、恢复日 |
| 已能连续划行 | 提高心肺耐力和动作稳定性 | 有氧基础、节奏练习、周计划与趋势 |
| 有训练经验 | 需要短间歇、功率方向刺激 | 单独标识的高强度课程与使用条件 |
| 家庭共享环境 | 小屏摆放在机身附近，手部操作不便 | 大数字、大按钮、少点击，音效可选 |
| 网络不稳定 | 跟练不能因断网中断 | 离线课程、计时和本地保存 |

主链路：查看今日建议 → 查看课程并开始 → 跟练后保存记录。首次配置与动作学习在主链路前完成；用户可随时重学。

### 3.2 P1：首版稳定后扩展

- 自定义课程与周计划，收藏、重复上一课程、更多技术专题。
- 自有或获授权的真人教学视频，手动下载、容量展示、字幕与慢放。
- 更完整的长期趋势、可选 CSV 导出和 .ics 日历导出。
- 高强度方向更多周期和进阶变式；依据内容审核与首版反馈逐项增加。
- 本地提醒入口或可选 Web Push；通知需要单独的服务、权限和交付验证。

### 3.3 P2：满足条件后评估

- 设备接入：按机型协议和浏览器能力验证，必要时单独评估原生桥接应用。
- 心率设备、厂商数据导入、云同步、多用户档案、AI 辅助解释。
- 摄像头动作分析：另行评估隐私、采集位置、模型精度、误判与端侧性能。

优先级用于排期；只有纳入具体发布范围的功能通过验收后，该发布才能标记完成。

## 4. 信息架构与页面

移动端四个顶层标签：**今日、训练、学习、记录**。设置从“今日”和“记录”的右上角进入，保持相同入口和路由。标签切换保留各自滚动位置；训练使用临时全屏视图，退出后返回原页面。

```text
今日 /today
  今日建议、当前计划、周训练摘要、调整与设置
训练 /training
  课程库、筛选、课程详情、自选计划、计划详情
学习 /learn
  新手入门、动作四阶段、常见错误、专题练习
记录 /history
  历史列表、记录详情、周摘要、数据管理
设置 /settings
  个人偏好、外观、提示音、安装、备份恢复、关于
训练视图 /session/:id
  准备 → 跟练 → 完成摘要
```

静态部署优先 Hash 路由以避免服务器深链接配置负担；若采用 History 路由，部署必须具备统一的 HTML 回退策略。URL 不包含健康状态、记录原文或个人数据。

### 4.1 页面规格

| 页面 | 页面内核心模块（优先 3–5 个） | 主要动作 | 关键状态 |
| --- | --- | --- | --- |
| 首次设置 | 经验与目标、时间安排、说明 | 保存偏好 | 跳过、校验失败、保存失败 |
| 今日 | 今日建议、当前计划、周摘要、动作提示 | 开始今日训练 | 无计划、休息日、漏练、训练待恢复 |
| 训练库 | 目标分段选择、筛选、课程列表 | 查看课程 | 无结果、课程不可用、内容版本更新 |
| 课程详情 | 目的与适用人群、强度与总时长、阶段预览、动作重点 | 开始训练 | 降级建议、高强度不适用、离线已就绪 |
| 计划详情 | 当前周、日期安排、进度、调整 | 使用计划 | 换计划提示、暂停、已完成、日期冲突 |
| 学习 | 入门路径、动作卡、错误对照、专题 | 开始学习 | 未学习、已浏览、自评未完成 |
| 教学详情 | SVG 分解、要点、常见错误、短练习 | 练习这个动作 | 静态替代动画、离线、标记已浏览 |
| 跟练 | 阶段与倒计时、目标强度、当前要点、操作栏 | 暂停 / 继续 | 准备、运行、暂停、挂起、保存受限 |
| 训练摘要 | 实际时长、手动读数、RPE 与感受 | 保存记录 | 完成、提前结束、保存中、保存失败 |
| 记录 | 周摘要、日期列表、单次详情 | 查看记录 | 空记录、离线、删除确认、编辑失败 |
| 设置 | 外观、偏好、声音、数据管理、安装 | 按分组执行动作 | 存储不可用、备份过期提醒、导入预览 |

### 4.2 首次配置

1. 选择经验：刚开始 / 能连续完成轻松训练 / 已有规律训练。
2. 选择主要目标和可用时间：动作学习、有氧耐力、运动习惯、高强度表现；每周 2–4 次，单次 15 / 20 / 30 / 45 分钟。
3. 展示推荐计划和可调整项，保存后进入今日。

每周天数、时长与经验均是推荐输入。用户选择高强度目标但经验不足时，解释理由并推荐动作基础计划，不伪装成已经测出其能力。

## 5. 动作规范教学设计

### 5.1 教学内容结构

先讲脚带、坐姿、握柄、空间与设备说明书，再讲完整划桨的四阶段。文字与自有 SVG 示意按内容版本绑定；不复制外部图片或视频文件。

| 阶段 | 用户能记住的一句话 | 图示重点 |
| --- | --- | --- |
| 入水位 Catch | 肩颈放松，从髋部前倾 | 头部自然、手臂伸展、小腿在舒适范围接近垂直 |
| 驱动 Drive | 腿先发力，再带躯干和手臂 | 蹬腿启动，随后躯干摆动、最后拉柄 |
| 结束位 Finish | 轻微后倾，手柄到下肋附近 | 核心支撑，肩低，手腕放松 |
| 回桨 Recovery | 先伸手，再前倾，最后屈膝 | 手柄越过膝盖后再逐渐前滑 |

基本顺序依据 [Concept2 动作教学](https://www.concept2.com/training/rowing-technique)。本项目将其改写为中文要点和自有示意，不把单一机型的阻力刻度推广为所有家用设备的标准。

### 5.2 教学交互

- 默认逐帧静态展示，支持“上一步 / 下一步”；可选整桨低速循环，可暂停。
- 用统一颜色区分当前教学部位，并以文字明确动作；不依赖颜色独立表达。
- 手动自检：肩颈是否紧张、驱动顺序是否稳定、回桨时手柄是否让开膝盖、是否出现不适。
- 浏览完成与动作自评分开记录。“已学习”表示浏览或练习过，不能标记为“动作已达标”。
- 简易练习使用短时、轻松强度；“仅腿练习、分段连接、回桨顺序”列为教学专题。[Concept2 技术练习](https://www.concept2.com/training/rowing-drills)

### 5.3 常见问题与针对性练习

| 自评问题 | 教学解释 | 推荐内容 | 表达边界 |
| --- | --- | --- | --- |
| 过早弯肘、手臂很快疲劳 | 驱动顺序可能不稳定 | 腿部启动与分段连接 | 用户自评，不声称已检测错误 |
| 弯腰伸手、过度前探 | 关注髋部前倾与舒适活动范围 | 入水位与躯干姿势 | 不给固定关节角度处方 |
| 回桨时手柄顶到膝盖 | 手与膝动作顺序需要协调 | 回桨顺序 | 不用加快速度掩盖顺序问题 |
| 肩颈紧张、握得过紧 | 关注放松握柄和肩部位置 | 肩颈与握柄 | 出现疼痛时停止练习并求助 |
| 划频上升但很快疲劳 | 节奏与用力需分别练习 | 稳定节奏与轻松划行 | 不把划频当作强度判定依据 |

错误分类参考 [Concept2 常见动作错误](https://www.concept2.com/training/improve-your-rowing-technique)；具体专题课时和组合为本项目设计，仍需内容审核。

### 5.4 设备差异

风阻、水阻、磁阻及复合阻力的档位不可直接对照；按对应说明书调节，起步采用容易控制动作的设置。应用首版不建议通用“阻力 5 档”，也不自动把某机型功率、卡路里或距离当作另一机型的同等负荷。

“针对性”优先指动作环节和能力目标：顺序、节奏、耐力和短间歇表现。划船涉及多部位协同，不宣传局部减脂，也不将高阻力划船包装成完整力量训练替代方案。

## 6. 训练内容与强度体系

### 6.1 有氧、无氧方向的产品表达

课程显示训练目的及工作 / 恢复结构。界面主分类使用“有氧基础”“节奏练习”“高强度间歇（无氧能力方向）”“技术与恢复”。“无氧方向”是课程目标标签，不能表示整次训练只有无氧供能；首版没有代谢测量，不输出“无氧分钟”或确定性的供能比例。

主观用力程度统一用 0–10 分 RPE，并在选择时显示中文解释，不混用 Borg 6–20 量表。CDC 使用 0–10 相对强度量表，将 5–6 视为中等、7–8 开始视为较高强度；中等强度通常能说话但难以唱歌，较高强度说几句话就要换气。[CDC 强度测量](https://www.cdc.gov/physical-activity-basics/measuring/index.html)

| 本项目目标 | 默认 RPE 标签 | 使用方式 |
| --- | --- | --- |
| 热身、恢复、动作学习 | 2–4，轻松 | 以动作稳定和舒适为主 |
| 有氧基础 | 4–6，轻松至中等 | 大部分入门课程采用；4 分不计为确定的中等强度分钟 |
| 受控节奏练习 | 6–7，中等至较吃力 | 对已有基础者开放，始终可降强度 |
| 短时高强度工作段 | 7–8，较吃力至很吃力 | 熟悉动作者的可选课，恢复充分 |
| 极限冲刺 | 9–10 | 首版不安排 |

以上课程映射是产品默认值，不是临床强度分区。划频提示只作节奏目标；同一划频可以对应不同功率和疲劳。首版不依据年龄公式硬设心率上限，不把低强度课直接命名为“已测定 Zone 2”。

### 6.2 课程数据要求

每门课程必须包含：目的、适用经验、总时长、难度、预备条件、热身 / 工作 / 恢复 / 放松阶段、RPE 目标、动作要点、低负担替代课、内容版本与审核状态。

首版以固定时长课程为主。距离课只有手动读数，无法自动识别到达目标，所以暂不作为自动推进的跟练课程；P1 可支持用户点击“已完成本段距离”。

| A04 稳定耐力 | 热身 5 分 + 连续 20 分 + 放松 5 分 | 30 分 | RPE 4–6 | 有基础者 |
| M01 受控节奏 | 热身 6 分 + 3 ×（节奏 3 分 / 轻松 2 分）+ 放松 5 分 | 26 分 | RPE 6–7 | 规律训练者 |
| H01 短间歇体验 | 热身 8 分 + 6 ×（较强 20 秒 / 轻松 100 秒）+ 放松 5 分 | 25 分 | RPE 7–8 | 满足高强度使用条件者 |
| H02 短间歇进阶 | 热身 8 分 + 6 ×（较强 30 秒 / 轻松 90 秒）+ 放松 5 分 | 25 分 | RPE 7–8 | 体验课稳定完成后可选 |
| R01 恢复划行 | 热身 3 分 + 轻松 6 分 + 放松 3 分 | 12 分 | RPE 2–3 | 恢复日，可选休息替代 |

入门采用短时练习和逐步增加训练的方向参考 [Concept2 起步建议](https://www.concept2.com/blog/getting-started-try-these-workouts)；具体课表以审核后的项目版本为准。

### 6.4 四周计划样例

计划日期是可移动的安排，默认训练之间安排非训练日。表内课程按第 6.3 节执行；每周列出的分钟是含热身和放松的总会话时长，不等同公共健康指南中的中等强度运动分钟。

**计划 P01：动作与习惯，默认每周 3 次**

| 周 | 第一次 | 第二次 | 第三次 | 总会话时长 |
| --- | --- | --- | --- | --- |
| 1 | T01 | T02 | A01 | 45 分 |
| 2 | T01 | A01 | A01 | 44 分 |
| 3 | T02 | A01 | A03 | 55 分 |
| 4 | A01 | A03 | A02 | 64 分 |

周 2 重复技能，不强求每周增加时间。用户不适应时重复当前周；“四周”表示模板长度，实际可用更长时间完成。

**计划 P02：有氧基础，默认每周 3 次；适合已能舒适完成 A02 的用户**

| 周 | 第一次 | 第二次 | 第三次 | 总会话时长 |
| --- | --- | --- | --- | --- |
| 1 | A02 | A03 | A02 | 74 分 |
| 2 | A02 | A03 | A04 | 79 分 |
| 3 | A04 | A02 | A04 | 85 分 |
| 4 | A02 | A03 | A02 | 74 分 |

第四周减量；不是每周不断增加刺激。用户能安排 2 次时选两节不同课程，不把第三次挤到同一天；可安排 4 次时第四次优先 R01 或休息，不自动增加高强度课。

**计划 P03：有氧与短间歇组合，默认每周 3 次；仅在满足高强度使用条件后由用户主动选择**

| 周 | 第一次 | 第二次 | 第三次 | 总会话时长 |
| --- | --- | --- | --- | --- |
| 1 | A02 | H01 | A02 | 75 分 |
| 2 | A02 | H01 | A02 | 75 分 |
| 3 | A02 | H02 | A04 | 80 分 |
| 4 | A01 | H01 | A01 | 55 分 |

默认示例为周一、周三、周六，至多一节高强度课，其余日休息或日常轻松活动。第三周 H02 仅在 H01 能稳定完成且无不适、用户主动选择后替换；否则重复 H01 或改 A01。第四周减量。每周只有两次时间时保留一节有氧与一节可选短间歇；当天疲劳可改轻松课或休息。P03 与课程一同由用户确认，P0 使用此计划结构；高强度使用条件继续生效。

### 6.5 计划推荐与调整规则

推荐采用可追踪规则，不使用 AI 或黑箱评分。规则版本暂定 `plan-rules-1`，每次生成记录输入版本、输出和原因。

1. 新手或主要目标为动作学习：推荐 P01。
2. 有基础且能舒适完成 A02，自评无不适：可推荐 P02。
3. 单次可用时间不足：选较短完整课程；不删减热身或放松来凑时长。12–13 分钟时可选 R01；不足 12 分钟建议休息或查看教学，不强行生成缩短课。R01 为恢复 / 轻松活动，不冒充完整入门主课。
4. 漏练：允许跳过、移到下一可用日或重复当前周，不自动补练、不叠加课次。
5. 若用户选择“很累”或报告不适：显示休息 / 更轻课程建议；不适时停止本次运动，相关提示见第 6.6 节。
6. 进阶依据：完成所选计划周至少 2 次、主观反馈可接受、无不适、动作自评稳定，才提示可进入下一周。用户主动选择，系统不在跨周时自动升级。
7. 高强度展示条件：自报有规律训练经验、确认已熟悉动作，且最近 14 天至少有 3 次完整、无不适的基础课记录；不足则可阅读课程详情并提供基础课。手动补录也要标来源，不能当成客观能力证明。
8. 高强度默认至多每周 1 次，间隔至少 48 小时；有疲劳则延后。该规则是保守的产品限制，不能证明任何个人适合高强度训练；高强度课不强制推荐，也不因解锁自动排入计划。
9. 同一次调整记录原因与规则版本。当前周模板、课程内容更新都不能重写已经保存的历史记录。

生成计划前逐节核对用户的单次时间上限；不符合时优先建议时间匹配的完整基础课组合，并预览替换后的名称、目标与总时长，用户采用后再写入 PlanAssignment。例如每次最多 20 分钟时，不直接分配包含 25 分钟课程的 P02；可选短课起步，或用户主动调整可用时间。不能先保存无法完成的原模板，再悄悄删减阶段。

### 6.6 训练安全与内容边界

- 上课前以简短、平静的文字提示：有已知健康问题、近期伤病或不确定能否开展较高强度运动时，先获得针对个人情况的专业建议。首版不提供康复处方。
- 跟练页常驻“暂停”，暂停页提供“结束并保存”；用户出现胸痛、头晕或明显异常不适时，提示停止运动并及时寻求医疗帮助。提示依据 [NHS 运动安全说明](https://www.cheshireandmerseyside.nhs.uk/your-health/surgery-school/getting-active/)，不把症状做成诊断评分。
- 动作变形或无法控制节奏时可降低用力、改轻松段或提前结束；已完成部分可保存，不使用失败、羞辱或惩罚性文案。
- 不承诺减重、局部减脂、提升百分比、疾病改善或热量消耗结果；不因默认目标而要求极限测试。
- 划船课程不能完整替代所有肌力训练。一般成年人还需要有氧与肌力活动的组合；首版不把自己的短起步计划宣称为满足全部公共健康活动建议。[CDC 成年人活动建议](https://www.cdc.gov/physical-activity-basics/adding-adults/what-counts.html)

内容状态：`draft → reviewed → published → retired`。保留来源、作者、审核者、日期、版权、内容版本；只有发布内容进入正式课程列表。历史会话保留已用版本快照。

## 7. iOS 风格 UI 与深色模式

### 7.1 视觉方向

整体接近 iOS 健康、设置、计时器的熟悉结构：大标题、系统字体、分组列表、圆角表面、轻量分隔线、底部标签栏与底部 Sheet。使用低饱和灰绿色点缀，不复制商标、系统截图或依赖玻璃材质；训练数字优先可读性。

系统字体使用 `-apple-system, BlinkMacSystemFont, system-ui, "PingFang SC", "Microsoft YaHei", sans-serif`。数字采用等宽数字特性；不下载或重新分发 SF 字体文件。

| --- | --- | --- |
| 大标题导航 | 语义 header、h1 与返回按钮 | 真实页面栈，返回保留筛选与滚动位置 |

### 7.4 深色模式行为

- 三选一：跟随系统 / 浅色 / 深色；默认跟随系统。偏好写 LocalStorage，失败时在当前会话生效并提示。
- 系统模式监听 `prefers-color-scheme` 实时变化；用户手动选择时优先手动偏好。
- 首屏绘制前设置主题，避免闪白；文档 `color-scheme`、页面 `theme-color` 与输入控件同步。
- 深色使用黑色底和分层表面，阴影轻量；以表面明度、边界与文字建立层级，不能单纯反相图像。
- SVG 使用 `currentColor` 和主题 Token；图表同时使用文字、线型或标记区分数据。
- 教学图在两种外观下都保持身体轮廓、动作箭头和文字可读。遵循系统外观偏好的方向参考 [Apple 深色模式指南](https://developer.apple.com/design/human-interface-guidelines/dark-mode)。

### 7.5 响应式、安全区与无障碍

- 支持 320–430px 手机窄屏、平板分栏及桌面；iPhone 主屏模式应用 `viewport-fit=cover` 与 `env(safe-area-inset-*)`。
- 高度使用动态视口单位并提供回退；键盘弹出时表单和保存按钮可滚动到达。避免固定高度导致底栏遮挡内容。
- 训练横屏可把计时与要点并排；不强制方向锁定。桌面最大正文宽度约 1120px，训练数字区保持集中。
- 禁止禁用页面缩放。200% 文本放大时动作区、Sheet 与表单不截断；超窄屏允许重排。
- 对比度目标：普通文字至少 4.5:1、大文字与关键交互边界至少 3:1；分隔装饰线不承担独立控件辨识。
- 所有图标统一 SVG：24×24 网格、约 2px 内边距、2px 圆头圆角描边，通过 `Icon` 组件集中维护。默认自有小图标集合；若引入图库只选一种并记录许可，不复制 SF Symbols 文件。
- 装饰图 `aria-hidden`；图标按钮有 `aria-label`。教学图提供文字等价内容。
- 跟练倒计时不每秒触发读屏播报；只播阶段切换、暂停和结束。声音可关闭，任何信息都可视觉获取。
- 支持 reduced motion；连续动画可停止。Sheet 支持 Escape 和明确关闭按钮，不以手势作为唯一退出方式。

## 8. 技术架构

### 8.1 技术选择与复用结论

工作区已有原生 JavaScript PWA，以及采用 React / TypeScript / Vite 的 iPhone 风格身体助手。本次仅检查其组件、数据与主题实现作为参考，未复制代码、共享数据库或修改兄弟项目。

本项目页面、计划和会话状态较多，建议采用 React + TypeScript + Vite，用原生 CSS 实现界面与主题；业务层保持纯 TypeScript。Vite 官方提供 `react-ts` 起步模板。[Vite 官方起步文档](https://vite.dev/guide/)

| 依赖 / 能力 | 必要性 | 成本与约束 |
| --- | --- | --- |
| React / React DOM | 可复用页面与组件、复杂训练状态展示 | 运行时依赖；初始化时测量压缩体积并核验版本与许可 |
| TypeScript / Vite | 数据契约、开发与静态构建 | 开发依赖；不按兄弟项目版本机械复制，保留锁文件 |
| IndexedDB | 会话、计划、记录的事务存储 | 浏览器原生；Repository 内封装错误、迁移与提交 |
| CSS / SVG | iOS 风格、主题、教学与小型图表 | 无 UI 框架；集中 Token、组件与 SVG 图标 |
| Service Worker / Cache API | 离线基础与可控更新 | 原生；发布脚本生成有版本的资源清单 |
| Vitest / Playwright（开发时评估） | 核心规则、事务恢复与跨页回归 | 仅开发依赖；Playwright 不能代替真实 iOS 验证 |

首版不引入完整移动 UI 框架、大型图表库、动画引擎、视频平台 SDK 或 AI SDK。若原生能力不足，再为单项能力做依赖评估；不为视觉相似度增加未经验证的大依赖。安装前检查维护状态、安全公告、许可、离线与构建影响。

## 9. 数据模型与指标口径

### 9.1 版本原则

数据库建议名称 `home-rower-db`，初始结构版本 `schemaVersion = 1`。应用版本、数据库结构版本、课程内容版本和推荐规则版本分别记录，不能互相代替。

长期用户实体使用 `id`、`createdAt`、`updatedAt`、`version`；ID 使用随机 UUID，日期时间保存 UTC ISO 字符串。计划日另存用户所在地的 `YYYY-MM-DD` 和创建时区；周统计按设置中的时区及周一起始日计算，不以 UTC 零点切分家庭训练。

### 9.2 主要实体

| 实体 / store | 关键字段 | 约束 |
| --- | --- | --- |
| UserProfile / profiles | experience、primaryGoal、weeklyDays、availableMinutes、machineCategory、timeZone | 不要求真实姓名、出生日期、体重；首版一个档案 |
| LessonProgress / lessonProgress | lessonId、contentVersion、viewedAt、selfChecks | 浏览与用户自评分开；不含自动动作评分 |
| PlanAssignment / plans | templateId、templateVersion、ruleVersion、startDate、status、courseSnapshots | 一个活动计划；换计划保留旧计划和历史关联 |
| PlannedSession / scheduledSessions | planId、localDate、courseSnapshot、status、linkedSessionId | 状态 planned / skipped / completed；提前结束不自动标完成 |
| SessionDraft / drafts | courseSnapshot、state、elapsedMs、revision、owner、leaseUntil、updatedAt | 一个活动草稿；保存与恢复时校验内容和游标 |
| WorkoutRecord / workouts | sessionId、planId?、startedAt、endedAt、completionStatus、stageResults、metrics、feedback、courseSnapshot | sessionId 唯一，防重复保存；记录可编辑且 version 递增 |
| AppMeta / meta | schemaVersion、appVersion、lastSuccessfulBackupAt、pendingRecovery | 存储维护信息，不能作为训练指标 |

课程与模板来自版本化静态内容包，不作为用户可写的数据库 store；计划和会话复制所需快照，保障内容升级与离线下的历史一致性。正式发布时新增审核通过的版本，不覆盖已经使用的快照。

### 9.3 实际类型契约

领域类型已实施，唯一实现来源见 [src/domain/types.ts](../../src/domain/types.ts)。原设计代码示例不再重复维护。实际课程字段为 course / stages / rpe，草稿累计时间为 elapsedMs；阶段位置和剩余时间从阶段时长派生。

跟练记录包含 course 快照与 stageResults；手动补录标为 manual-entry，设备手填读数标为 manual，派生配速标为 derived。首版指标只支持 whole-session 范围，设备来源及工作段独立读数属于后续能力。计划课程快照放在 scheduledSessions，当前不记录 practiceCount。

实际备份字段、校验和范围由 src/domain/validation.ts 与 src/application/service.ts 维护；schemaVersion 为 1。

### 9.4 记录口径

- **实际训练时长**：应用处于运行阶段的累计时长，包含热身、工作、轻松恢复与放松；排除倒数准备、主动暂停和后台挂起。首版无法客观确认用户是否持续划动，详情标注“跟练计时”，补录标注“手动记录”。
- **工作段时长**：只累加工作阶段实际执行时长，不包含恢复段。摘要同时展示总会话时长和工作时长，避免误读。
- **完成**：所有必需阶段均到达正常结束，且保存成功；提前结束或跳过工作段保存为 `ended-early`。计划完成度只统计 completed，周训练次数和实际分钟可包括提前结束记录并标明。
- **距离**：用户填写设备显示读数，可为空。空值显示“未记录”，不填 0，不推测设备距离。
- **平均配速**：仅当距离大于 0、时间和距离覆盖相同范围时，计算 `同范围秒数 ÷ 同范围米数 × 500`。整次训练数据不生成工作段配速；来源 derived，记录公式版本。
- **划频 / 功率 / 热量**：首版只允许可选手动输入相应机器读数并标“设备读数手填”。不依据计时推算功率，不提供未经定义的消耗热量估计。
- **周摘要**：训练次数、实际时长、记录完整率；首版不宣称已验证的有氧达标率、VO₂max、无氧负荷或恢复评分。
- **趋势比较**：同机型、同课程、同范围才可做相近条件比较；设备未知则只展示原始历史，不输出可信度不足的提升百分比。

### 9.5 校验与错误

建议初始范围：单次有效时长 1–21600 秒、距离大于 0 且不超过 100000 米、RPE 0–10、备注最多 300 字；超范围不截断、不静默修正，明确指出字段并允许改正。后续设备读数的边界单独评估。

存储错误以可操作信息呈现，例如：“记录未保存到本机。当前内容仍在页面内，请重试或导出这次记录。”错误日志只含错误码、应用版本、实体 ID 和流程阶段，不写健康备注、完整备份或敏感输入。

## 10. 跟练状态机、计时与恢复

### 10.1 状态与操作

```text
idle → ready → running → completed → saving → saved
                 ↓ ↑         ↑          ↓
                paused ──────┘        saveFailed → saving
                 ↑ ↓
               suspended

running / paused / suspended → endedEarly → saving
```

- `ready`：用户查看阶段、确认摆放并点击开始；音频初始化必须由用户操作触发。
- `running`：显示当前段及下一段，可暂停。阶段切换只发生一次；末段结束进入 completed。
- `paused`：时钟停止，不自动进入下一段；提供继续、结束并保存。
- `suspended`：页面隐藏、锁屏或恢复时发现计时中断；展示恢复说明并由用户确认继续。
- `completed` / `endedEarly`：尚未持久保存的摘要，明确显示待保存。
- `saving`：保存禁重复点击；保存草稿保留直到事务提交成功。
- `saved`：允许查看记录或返回今日，不能重复创建同一个 sessionId。
- `saveFailed`：摘要不丢弃，显示重试与单次 JSON 下载；下次启动继续恢复待保存摘要。

提前关闭运行页面先暂停，再显示“继续训练 / 结束并保存”；丢弃草稿是单独的危险操作，需要说明影响和确认。

### 10.2 前台计时算法

- 使用单调时钟 `performance.now()` 计算前台经过时间，显示刷新使用定时器或动画帧；不把每次 `setInterval` 回调作为一秒累计，避免节流漂移。
- 每次推进根据实际时间差查找阶段边界；对于多个被跨越的阶段，音效只提示当前阶段，不能连播遗漏提醒。
- 总阶段时长从展开后的 stages 求和，校验与 plannedDurationSeconds 相同。
- 切换阶段、暂停、继续、提前结束立即提交草稿；运行中建议每 5 秒提交一次检查点，明确这是恢复粒度而非永久保存保证。
- DOM `visibilitychange` 进入 hidden 时转 suspended，并尽力保存检查点；不能依赖该事件必然触发或提交成功。
- 同一前台段内发现异常长调度间隔（初稿阈值 10 秒，真机测量后调整）时，优先挂起确认，不自动把缺失时间跨越多个阶段算成训练完成。
- `Date.now()` 仅用于记录真实日历时间和异常判断；系统调时、时区变化不影响单调前台计时。

### 10.3 挂起、刷新与跨窗口

恢复时展示“训练曾中断，已恢复至最近保存的位置；中断期间未计入训练”。刷新、进程回收或页面隐藏期间不从日历时间补算运动，不自动播放，不自动标记为 completed。

恢复保留课程版本、已执行阶段和已提交时长；未提交的尾部可能损失最多一个检查点周期，异常存储时可能更多。界面只报告实际读到的数据，不许宣称零损失。

仅允许一个活动会话。跨标签页或多个 PWA 窗口通过 IndexedDB 事务维护 owner、revision 与可恢复的租约；BroadcastChannel 可用于通知但不能作为唯一锁。第二窗口默认只读查看状态。接管需暂停旧运行、校验最新 revision 并明确提示，防止两窗口互相覆盖。

结束会话在单个事务内写 WorkoutRecord、关联计划状态并清理草稿；等待 `transaction.oncomplete` 后才显示已保存。请求 `onsuccess` 不等同事务提交成功。异常或冲突回滚后保留可重试草稿。

### 10.4 提示音与屏幕常亮

提示音只在用户启用并开始训练后初始化；音频拒绝、静音、其他声音打断时用文字提示，不影响训练流程。计时始终可见，不承诺锁屏后台播报。

屏幕常亮通过 WakeLockAdapter 按需申请并释放；恢复前台时可重试，失败显示“屏幕常亮不可用，请保持页面在前台”。WebKit 在 Safari 18.4 对主屏 Web App 的 Screen Wake Lock 做过修复，因此必须覆盖实际主屏模式验证，不能只测浏览器标签页。[WebKit 18.4 发布说明](https://webkit.org/blog/16574/webkit-features-in-safari-18-4/)

## 11. PWA、离线与 iOS 能力边界

### 11.1 Manifest 与安装

- 明确应用 name、short_name、稳定 id、start_url、scope、display、theme_color、background_color；安装图标准备 192 / 512 PNG 与 maskable 版本，iOS 增加 apple-touch-icon。安装图标属于平台资源，正式 UI 仍采用 SVG。
- 本地开发使用 localhost；iPhone 真机访问电脑局域网地址时不能假设普通 HTTP 具备 Service Worker 等安全上下文能力，使用受信任 HTTPS 的测试站点或证书方案。
- 发布根目录或子路径部署均要验证资源 base、manifest 的 start_url / scope 与 SW 范围；一个配置来源生成路径，不硬编码域名。
- iOS 提供与实际系统界面一致的“分享 → 添加到主屏幕”文字指引；支持自动安装提示的环境再显示自动按钮，不伪造 iOS 原生安装弹窗。

### 11.2 离线资源与缓存

| 资源 | 策略 | 边界 |
| --- | --- | --- |
| 有内容哈希的 JS / CSS / SVG | Cache First + 构建清单预缓存 | 同一构建版本完整安装后才可用 |
| 应用 HTML / 导航 | Network First，超时回退已缓存 shell | 回退 shell 必须有配套构建资源，避免新旧混用 |
| 内置课程、教学与计划 | 随构建版本打包并预缓存 | 核心图文不依赖外部站点 |
| 未来内容更新清单 | Network First，使用经验证的本地旧版本 | 内容变化不能中途替换当前课快照 |
| 未来大型视频 | 用户手动下载，独立缓存配额 | 首版不预缓存；明确离线可用与删除入口 |
| 用户训练数据 | IndexedDB Repository | 不存入 SW 响应缓存，不作为远端请求内容 |

离线就绪以关键 shell、课程与图文预缓存完成为准，首次访问未完成不能宣称已可离线。首次完全无网络时，没有预缓存的设备只能显示浏览器网络错误；这不属于可离线使用的安装状态。

训练过程中断网不应改变当前阶段或保存逻辑。离线资源损坏时明确说明哪些功能受影响，不清空数据库。

### 11.3 更新与旧缓存清理

1. 新 SW 安装到 waiting，校验完整缓存；前台提示“有新版本”。
2. 活动训练、待保存摘要或导入期间不自动激活、不强制刷新；允许稍后更新。
3. 用户执行更新前保存状态，并与其他窗口协调。版本不兼容的旧窗口进入只读或要求关闭，不能让旧代码继续写新结构。
4. 数据库迁移在事务中完成，迁移前提供或生成本地可下载备份。失败保留原结构，进入恢复模式；不要删库重试。
5. 新版本验证离线资源和控制关系后清理本项目旧缓存；不得删除其他应用缓存或跨项目数据库。
6. 回滚同样需要结构兼容性评估。静态文件回滚不能自动撤销数据库迁移；破坏性 schema 变更另写 ADR 和恢复方案。

Cache 名称建议 `home-rower:<app-build>:shell`，不把 schemaVersion 当作唯一缓存版本。开发模式默认不注册生产 SW，真机验收另用正式构建。

### 11.4 兼容目标与降级矩阵

首版建议基线 iOS / iPadOS 17 及以上；18.4 及以上作为屏幕常亮优先验证范围。发布时冻结实际支持系统与设备列表，对当时稳定系统和前一主要版本做回归，不在本设计阶段宣称已经支持任何版本。

| 安装 | 添加到主屏幕指引，验证 manifest 与图标 | 在 Safari 直接使用 |

## 12. 导出、导入、备份与隐私

### 12.1 JSON 备份格式

导出格式固定顶层 `format = "home-rower-backup"`，包括 exportVersion、schemaVersion、appVersion、contentVersion、exportedAt、实体计数与 data；导出前生成一致性快照。文件名示例 `home-rower-backup-2026-10-08.json`。

备份包括用户档案、学习进度、计划与记录；包含草稿时注明为暂停检查点，导入不自动运行。不打包教学媒体缓存，不导出秘密或内部日志。主题是简单设置，允许随备份携带但导入时单独勾选。

首版 JSON 为未加密数据，下载前简短说明文件可能包含训练与健康相关反馈，保存到用户选择的位置；不自动上传。每 30 天且存在新增记录时可温和提醒备份，允许关闭。

### 12.2 导入流程与冲突

严格执行：选文件 → 校验 → 预览 → 确认 → 导入 → 核验。

1. 初始文件上限 10MB、记录上限 10000 条。检查扩展名与解析结果，不信任 MIME；校验格式、版本、字段、范围、关联 ID、重复、危险键与数组规模。
2. 未来版本先拒绝并解释需要升级应用；历史版本经显式 migration 生成暂存结果，不能未经验证直接写当前数据库。
3. 预览显示新增、重复、冲突、草稿及设置数量。无效项列出原因；默认拒绝整个无效备份，不静默丢行后宣称成功。
4. 默认“合并、保留本机冲突项”。冲突由 id + version + 内容比较识别，同 version 但内容不同也算冲突；不能单凭日期自动覆盖。
5. “覆盖冲突”或“完整替换”明确列出影响，先完成本机快照导出，用户确认后才提交。若备份导出失败，不执行破坏性替换。
6. 用户确认后重新校验数据库 revision，确保预览之后没有其他写入改变冲突。大文件分批解析进暂存，但最终修改是原子提交；导入事务中不能插入任意网络等待。
7. 提交后核验实体数量、关联完整性、随机样本与 schemaVersion；核验失败转恢复流程并保留导入前快照。错误时不能自动删除原库。

草稿冲突单独处理：只能保留一个活动草稿；外部草稿默认作为可选暂停恢复项，不覆盖本机训练。导入期间禁止开始新训练和计划变更，其他窗口同步只读状态。

### 12.3 数据生命周期与隐私

- 所有训练数据首版留在当前浏览器 / 安装环境，没有后台账号数据库；浏览器与主屏容器之间的共享 / 隔离状态需要真机确认，不宣称天然跨容器同步。
- 不收集定位、通讯录、摄像头、麦克风和广告标识；不引入第三方埋点。提示音不需要麦克风权限。
- 网络请求仅用于应用静态资源和用户主动访问的教学来源，不能把训练记录或健康备注塞入 URL。
- 无痕模式、清理网站数据、卸载或系统存储回收都可能影响本地数据。设置中说明本机保存的边界，提供备份，不承诺永久可靠存储。
- 可检查 `navigator.storage.estimate()`；可选请求 persistent storage，但拒绝或不支持不能阻止核心功能。空间不足时不删除训练记录，优先让用户清理可重建媒体缓存。
- 若 IndexedDB 不可用，明确进入临时会话模式；允许学习与有限跟练，提示关闭将丢失未导出的数据，不能显示“已保存”。不静默转用 LocalStorage 保存整套记录。
- 删除单条记录采用确认或可验证的撤销；完整重置说明档案、计划、草稿及记录影响，先建议备份并二次确认。

### 12.4 安全实现要求

用户输入按普通文字渲染，不插入不可信 HTML / SVG；外部链接固定允许列表、使用安全的新窗口属性。备份键名不直接深度合并到配置或原型对象。

部署配置 Content Security Policy 与安全响应头，避免 `unsafe-eval`；首屏主题脚本采用构建哈希或受控外部脚本方案。生产日志不记录健康原文。未来云服务 / AI 才需要单独设计服务端与秘密管理，API Key 不能进入前端构建。

## 13. 后续设备接口契约

首版只定义领域接口与手动数据来源，不实现空的“连接成功”按钮，不自动申请蓝牙权限。

```ts
interface DeviceAdapter {
  getStatus(): 'unsupported' | 'disconnected' | 'connecting' | 'connected' | 'error';
  getCapabilities(): { read: boolean; write: boolean; metrics: string[] };
  connect(): Promise<void>;
  disconnect(): Promise<void>;
  read(): Promise<NormalizedDeviceSample>;
  write(command: DeviceCommand): Promise<void>; // 无写能力时返回明确的不支持错误
}
```

具体类型后续按协议设计，统一单位、时间戳、来源、质量与设备标识。设备中断后回到手动模式，不补造读数；读数延迟和缺失必须显式显示。首版不下发阻力或控制机械设备；写接口仅是未来契约，占位不代表已经授权或实现硬件控制。

设备接入前验收：品牌型号、协议与授权、浏览器环境、实机连接、断连恢复、单位与累计量校验、隐私与电量消耗。iOS 如需原生壳或桥接，属于新的架构决策，不在 PWA 中静默增加。

### 14.2 内容审核

- 动作图文与练习顺序逐项检查，版本和版权来源可查。
- 所有课程重复、总时长、强度与替代课校验通过。
- 审核者明确适用人群、热身放松、高强度条件、疲劳反馈和停止提示。
- 高强度课不会因用户勾选目标或跨周日期自动开始。
- 推荐解释明确来自用户输入与产品规则，不能显示为运动能力检测结论。

### 14.3 性能目标（待测基线）

初稿目标：不含媒体的首屏关键 JS + CSS 压缩传输量不超过 250KB；核心离线资产不超过 5MB。若测量超出，先列出组成与理由再调整预算，不能省掉数据保护换取体积。

在记录实际设备、网络与构建版本的前提下，目标 LCP ≤ 2.5 秒、CLS ≤ 0.1、关键交互响应约 200ms 内。先测量实际基线，离线冷启动单独计时，不把 Lighthouse 分数当作全部验收。

以 1000 条训练记录验证列表分页、周统计、导出与主线程任务；导入 10000 条的上限另做容量测试。统计不每次从 UI 全量扫描，图表懒加载，输入与导入处理中不冻结界面。

### 14.4 完成标准

纳入发布范围的 P0 全部完成，核心与异常路径验证通过；内容审核可查；深浅主题、SVG、无障碍、离线安装、事务保存、恢复与更新通过实际测试；文档与实现一致，风险和未完成范围在状态文件中说明。

测试结果使用 PLANNED / IMPLEMENTED / PARTIALLY DONE / DONE / BLOCKED。未经执行的检查保持 PLANNED；实现后缺真机证据不得写成 DONE。
